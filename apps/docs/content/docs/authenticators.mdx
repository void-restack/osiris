Osiris provides multiple authentication methods to securely connect MCPs with external services and user wallets. Each authenticator is designed for specific use cases and security requirements.

## No Client IDs or Secrets Required

Developers **do not need to acquire or manage any client IDs or secrets** for any authenticator. All authentication flows are securely handled by the Osiris Auth Hub:

- **No manual setup** of OAuth credentials for Google, GitHub, Discord, etc.
- **No risk** of leaking sensitive secrets in your codebase or deployment.
- **Faster onboarding**—just use the Osiris SDK and everything works out of the box.

## Secure by Design: Auth Hub & Action Logging

- **All authentications and token management** are handled by the Osiris Auth Hub, providing a unified, secure, and up-to-date authentication layer for every MCP.
- **Every action taken by an MCP is logged** and made visible to the user in a comprehensive dashboard.
- **Users can review all actions** performed on their behalf, giving them full transparency and confidence in both the MCP and its developer.
- **Developers benefit from user trust** and can focus on building features, not auth infrastructure.

## OAuth Authenticators

OAuth authenticators provide secure integration with third-party services using industry-standard OAuth 2.0 flows.

### Google Authenticator

Connect to Google services including Gmail, Calendar, Drive, and Sheets.

```typescript
import { GoogleAuthenticator } from '@osiris-ai/sdk';

const googleAuthenticator = new GoogleAuthenticator(
    ['https://www.googleapis.com/auth/gmail.send', 'https://www.googleapis.com/auth/calendar'],
    {
        clientId: process.env.GOOGLE_CLIENT_ID,
        clientSecret: process.env.GOOGLE_CLIENT_SECRET,
        redirectUri: process.env.GOOGLE_REDIRECT_URI,
    }
);
```

**Supported Scopes:**
- `gmail.send` - Send emails
- `gmail.readonly` - Read emails
- `calendar` - Manage calendar events
- `drive` - Access Google Drive files
- `sheets` - Read and write Google Sheets

**Use Cases:**
- Email automation and management
- Calendar scheduling and event creation
- Document and file management
- Spreadsheet data analysis

## Wallet Authenticators

Wallet authenticators provide secure access to blockchain wallets with policy enforcement.

### Turnkey Wallet

Enterprise-grade wallet infrastructure with hardware-backed security.

```typescript
import { TurnkeyWallet } from '@osiris-ai/sdk';

const turnkeyAuthenticator = new TurnkeyWallet({
    organizationId: process.env.TURNKEY_ORGANIZATION_ID,
    apiPublicKey: process.env.TURNKEY_API_PUBLIC_KEY,
    apiPrivateKey: process.env.TURNKEY_API_PRIVATE_KEY,
    baseUrl: process.env.TURNKEY_BASE_URL
});
```

**Features:**
- Hardware-backed security with HSMs
- Multi-signature wallet support
- Policy engine integration
- Enterprise-grade compliance

**Use Cases:**
- DeFi protocol interactions
- Token transfers and swaps
- Smart contract deployment
- Institutional trading

**Policy Integration:**
```typescript
// Policy engine automatically validates transactions
const { token, context } = getAuthContext("osiris");
const client = new EVMWalletClient(hubBaseUrl, token.access_token, context.deploymentId, chainId);

try {
    const transaction = await client.signTransaction(abi, serializedTx, address);
    console.log("✅ Transaction approved by policy engine");
} catch (error) {
    if (error.message.includes('policy')) {
        console.log("🚫 Transaction blocked by wallet policy");
    }
}
```

## Secret Sharing Authenticators

Secret sharing authenticators provide secure access to databases and APIs without exposing credentials.

### PostgreSQL Secret Sharing

Secure database access with encrypted credential storage.

```typescript
import { PostgresSecretSharingAuthenticator } from '@osiris-ai/sdk';

const postgresAuthenticator = new PostgresSecretSharingAuthenticator();

// Usage in MCP tools
const context = getAuthContext();
const response = await fetch(`https://api.osirislabs.xyz/v1/hub/action/${context.deploymentId}/postgres`, {
    method: "POST",
    headers: {
        'Authorization': `Bearer ${context.token}`,
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({
        sql: `SELECT * FROM user_data WHERE user_id = $1`,
        params: [context.userId]
    })
});
```

**Features:**
- Encrypted credential storage
- User-controlled access
- Automatic connection management
- Query parameter sanitization

**Use Cases:**
- User data storage and retrieval
- Analytics and reporting
- Configuration management
- Audit logging

## Authentication Flow

### OAuth Flow

1. **Authorization Request**: User is redirected to OAuth provider
2. **User Consent**: User grants permissions to the MCP
3. **Authorization Code**: Provider returns code to callback URL
4. **Token Exchange**: MCP exchanges code for access/refresh tokens
5. **Token Storage**: Tokens are securely stored in database
6. **API Access**: Subsequent requests use stored tokens

```typescript
// Automatic token management
const context = getAuthContext();
if (!context.tokens) {
    throw new Error('No tokens available. Please authenticate first.');
}

const gmail = createHubGmailClient({ hubBaseUrl: process.env.HUB_BASE_URL! });
const emails = await gmail.users.messages.list({ userId: 'me' });
```

### Wallet Flow

1. **Wallet Request**: MCP requests wallet access
2. **Policy Validation**: User's wallet policies are loaded
3. **Transaction Creation**: MCP creates transaction
4. **Policy Check**: Policy engine validates transaction
5. **User Approval**: If required, user approves transaction
6. **Execution**: Transaction is signed and broadcast

```typescript
// Policy-enforced wallet operations
const { token, context } = getAuthContext("osiris");
const client = new EVMWalletClient(hubBaseUrl, token.access_token, context.deploymentId, chainId);

// This will be automatically validated against user's policies
const result = await client.signTransaction(abi, serializedTx, address);
```

## Security Features

### Multi-Tenant Isolation

Each deployment has isolated authentication and data:

```typescript
const context = getAuthContext();
console.log('User ID:', context.userId);
console.log('Deployment ID:', context.deploymentId);

// All operations are automatically scoped to the current user
const userEmails = await fetchUserEmails(context.userId);
```

### Token Management

- **Automatic Refresh**: OAuth tokens are automatically refreshed
- **Secure Storage**: Tokens are encrypted at rest
- **Scope Validation**: Only requested scopes are granted
- **Expiration Handling**: Expired tokens trigger re-authentication

### Policy Enforcement

Wallet transactions are protected by user-defined policies:

```typescript

// - Transfers above daily limits
// - Transactions to unknown addresses
// - Excessive gas fees
// - Unauthorized contract interactions
```

## Best Practices

### 1. Minimal Scopes

Request only the scopes your MCP actually needs:

```typescript
// ✅ GOOD: Minimal scopes
const scopes = ['gmail.send']; // Only send emails

// ❌ BAD: Excessive scopes
const scopes = ['gmail.full_access']; // Full Gmail access
```

### 2. Secure Credential Storage

Never hardcode credentials in your application:

```typescript
// ✅ GOOD: Environment variables
clientSecret: process.env.GOOGLE_CLIENT_SECRET

// ❌ BAD: Hardcoded secrets
clientSecret: "your-secret-here"
```

### 3. Error Handling

Provide clear error messages for authentication failures:

```typescript
try {
    const context = getAuthContext();
    if (!context.tokens) {
        throw new AuthContextError('Authentication required');
    }
} catch (error) {
    if (error instanceof AuthContextError) {
        return {
            content: [{
                type: 'text',
                text: `🔐 Please authenticate: ${error.authorizationUrl}`
            }],
            isError: true
        };
    }
}
```

### 4. Policy Configuration

Set appropriate wallet policies for your use case:

```typescript
// For trading MCPs
const tradingPolicy = new PolicyBuilder()
    .allowTransfer(
        { addressInList: trustedExchanges },
        { bigIntMax: "1000000000000000000" } // 1 ETH max
    )
    .denyUnlimitedApprovals()
    .build();
```

## Getting Credentials

To use OAuth authenticators, you need to register your application with each service:

1. **Google**: [Google Cloud Console](https://console.cloud.google.com/)
2. **GitHub**: [GitHub Developer Settings](https://github.com/settings/developers)
3. **Discord**: [Discord Developer Portal](https://discord.com/developers/applications)
4. **Linear**: [Linear API Settings](https://linear.app/settings/api)
5. **Slack**: [Slack API](https://api.slack.com/apps)
6. **Notion**: [Notion Developers](https://developers.notion.com/)

For Turnkey wallet access, contact [Turnkey](https://turnkey.com/) for enterprise setup.
